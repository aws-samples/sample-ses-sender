# CLAUDE.md — Claude Code Project Instructions

## Project

AWS SES bulk email management platform. FastAPI backend + Next.js frontend + MySQL, deployed via Docker Compose.

## Quick Context

- **Backend**: Python 3.11, FastAPI, SQLAlchemy, Alembic, Boto3. DDD structure under `backend/domain/{auth,identity,template,audience,sending}/`.
- **Frontend**: Next.js 16, React, Tailwind CSS, TypeScript. All UI components in `frontend/app/components/shared.tsx`. Frontend proxies `/api/*` to backend via `app/api/[...path]/route.ts`.
- **Database**: MySQL 8, 7 tables. Alembic migrations auto-run on startup.
- **AWS**: SES v2 for sending, CloudWatch for metrics, SNS+SQS for per-email event tracking, Bedrock for AI template optimization.

## Code Style

- Backend: each domain has `models.py`, `schemas.py`, `service.py`, `router.py`. Business logic in service, not router.
- Frontend: functional components, hooks from `shared.tsx` (`useAuth`, `useToast`, `useConfirm`). API calls use `fetch()` with `authH(token)` headers.
- Pydantic schemas for all request/response models. SQLAlchemy ORM models.
- Alembic migrations use manually assigned revision IDs (not autogenerated hashes).

## Key Files

- `backend/main.py` — App entry, Alembic migration, SQS polling thread, scheduler thread, image upload endpoint
- `backend/core/config.py` — All environment variables
- `backend/core/ses.py` — SES v1/v2 clients, `get_send_quota()`
- `backend/domain/sending/service.py` — Core sending logic (800+ lines): `send_bulk_email()`, `_do_send()`, `get_user_dashboard()`, `execute_scheduled_job()`, `_calc_next_run()`, `_parse_ai_json()`
- `frontend/app/components/shared.tsx` — All shared UI components and utilities
- `frontend/next.config.ts` — Currently empty (rewrites removed, using route handler proxy)

## Common Tasks

### Add a new API endpoint
1. Add Pydantic schema in `domain/X/schemas.py`
2. Add business logic in `domain/X/service.py`
3. Add route in `domain/X/router.py`

### Add a new database column
1. Add column to model in `domain/X/models.py`
2. Create migration: `backend/alembic/versions/REVISION_ID_description.py` (use manual revision ID, set `down_revision` to current head)
3. Migration auto-runs on next container restart

### Add a new frontend page
1. Create component in `frontend/app/pages/user/` or `shared/`
2. Import and register in `UserApp.tsx` (or `AdminApp.tsx`) with menu entry

## Important Patterns

- **Async sending**: `send_bulk_email()` returns immediately, spawns `_do_send()` thread
- **Rate limiting**: `min(SES_MAX_SEND_RATE, 50)` emails per second, 1s pause between batches
- **Daily quota**: checked before sending, rejects with 429 if exceeded
- **Unsubscribe**: `List-Unsubscribe` headers added only when `UNSUBSCRIBE_BASE_URL` is set
- **Template variables**: `{{name}}`, `{{email}}`, custom contact attributes, `{{unsubscribe_url}}`
- **AI optimization**: Bedrock → custom `_parse_ai_json()` extracts fields individually (not `json.loads`) because HTML in JSON breaks standard parsing

## Do Not

- Do not hardcode AWS region — always use `AWS_REGION` from config
- Do not use SES v1 `send_bulk_templated_email` — project uses SES v2 `send_email` per recipient
- Do not add `NEXT_PUBLIC_*` env vars for API URL — frontend uses `/api` proxy
- Do not expose backend port 8000 externally — only frontend port 3000
- Do not modify existing migration files — always create new ones
